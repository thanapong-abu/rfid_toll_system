SYSTEM ARCHITECTURE

From Scan to Open — in 1.5 Seconds

A complete technical walkthrough of the hardware-to-software pipeline powering the RFID Toll Collection System.

🚘

Step 1: Vehicle Approach

The vehicle arrives at the toll plaza. The mounted RFID tag enters the RC522 reader's electromagnetic field (effective range: 3–5cm).

📡

Step 2: Hardware Scan

The Arduino-driven RC522 module captures the 4-byte hexadecimal UID of the tag. The buzzer sounds a short beep to confirm read success.

🔌

Step 3: Serial Transmission

The Arduino packages the raw UID string (e.g., 8D 20 06 85) and transmits it to the connected PC via USB Serial communication at 9600 baud.

🗄️

Step 4: Database Query

The Python middleware script intercepts the serial data and queries the local SQLite database to verify the vehicle's registration and check if wallet_bal >= 100.

✓

Authorized Path

Toll fee is atomically deducted from the database. Transaction is recorded. The PC sends byte 1 to the Arduino.

Hardware Response:

Green LED activates. SG90 Servo rotates from 0° to -90° (Gate Opens). Remains open for 5 seconds.

✗

Denied Path

Insufficient funds or unknown tag detected. Transaction is flagged as Denied. The PC sends byte 0 to the Arduino.

Hardware Response:

Red LED activates. Buzzer emits a 2-second error tone. Servo remains locked at 0° (Gate Closed).

🛡️
Security Mechanism: Anti-Passback A hardcoded 10-second cooldown is enforced in the Python middleware after every successful scan. If a vehicle's tag remains in the reader's field, or is scanned twice rapidly, the system ignores the subsequent reads to prevent double-deduction of the toll fee.
